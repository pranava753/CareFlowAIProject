# CareFlow -- AI Care Coordination Assistant (M1-M8)

A multi-agent assistant for a multi-specialty outpatient clinic chain: it
triages patient intake messages, answers policy/insurance questions from
clinic documents (grounded RAG), tracks referrals and eligibility via mock
EHR tools, and orchestrates the whole intake -> eligibility -> referral flow
as a LangGraph workflow with a human-in-the-loop checkpoint -- while
refusing to give clinical/diagnostic advice, with retries/circuit-breaking
around the mock EHR calls and LangFuse tracing throughout.

This build covers all **8 milestones** of the CareFlow capstone.

No real PHI is used anywhere. All patients, encounters, eligibility,
appointments, referrals, and intake messages are synthetically generated by
[`generate.py`](generate.py) (Synthea/Java wasn't available on this machine,
so mock tables matching Synthea's column shapes are generated in Python
instead of running real Synthea).

## What's built

| Milestone | What | Where |
|---|---|---|
| M1 | Intake message -> validated `PatientRequest` (Pydantic) via a LiteLLM structured-extraction call | [app/models/patient_request.py](app/models/patient_request.py), [app/agents/intake.py](app/agents/intake.py) |
| M2 | Scheduling/insurance agent with 4 tool categories: mock EHR appointments, mock insurance eligibility, co-pay calculator, flag-for-human | [app/agents/insurance_agent.py](app/agents/insurance_agent.py), [app/tools/](app/tools/) |
| M3 | Session memory (per-conversation) + long-term patient memory (synthetic, de-identified, SQLite) + base Qdrant index over the policy corpus | [app/memory/](app/memory/), [app/rag/index.py](app/rag/index.py) |
| M4 | Production RAG: hybrid (dense Qdrant + BM25) search with reciprocal-rank fusion, cross-encoder reranking, LLM-judge groundedness gate | [app/rag/retriever.py](app/rag/retriever.py), [app/rag/rerank.py](app/rag/rerank.py), [app/rag/groundedness.py](app/rag/groundedness.py), [app/rag/qa_agent.py](app/rag/qa_agent.py) |
| M5 | LangGraph workflow: intake -> clinical review -> (human-in-the-loop checkpoint if flagged) -> eligibility -> referral routing -> finalize, durably checkpointed in SQLite so a paused run survives a process restart | [app/graph/intake_workflow.py](app/graph/intake_workflow.py) |
| M6 | Full agent team (Intake, Insurance, Referral Tracker, Clinical Safety Reviewer) + mock EHR/scheduling system exposed as an MCP server | [app/agents/referral_agent.py](app/agents/referral_agent.py), [app/agents/clinical_safety_agent.py](app/agents/clinical_safety_agent.py), [app/mcp_server/server.py](app/mcp_server/server.py), [app/tools/mcp_client.py](app/tools/mcp_client.py) |
| M7 | LangFuse tracing (via LiteLLM's native callback) + retry/circuit-breaker/graceful-fallback hardening around every mock EHR/insurance call | [app/observability/tracing.py](app/observability/tracing.py), [app/resilience/](app/resilience/) |
| M8 | 20-case golden eval set (weighted toward refusal) + FastAPI service wrapping the whole pipeline | [data/careflow/eval/golden_eval.jsonl](data/careflow/eval/golden_eval.jsonl), [scripts/run_golden_eval.py](scripts/run_golden_eval.py), [app/api/main.py](app/api/main.py) |

Guardrails against clinical/diagnostic advice ([app/guardrails.py](app/guardrails.py))
are checked *before* either agent's main logic runs, including the "I'm a
doctor, clinician to clinician" bypass attempt -- which the Clinical
Escalation Standard document explicitly says has no exceptions.

## Setup

```bash
cd CareFlow
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
copy .env.example .env          # then fill in OPENAI_API_KEY
```

Embeddings (`sentence-transformers/all-MiniLM-L6-v2`) and the reranker
(`cross-encoder/ms-marco-MiniLM-L-6-v2`) run locally -- no extra API key,
but they download (~100-200MB total) on first use. Qdrant runs in local
embedded mode (`data/careflow/qdrant_store/`) -- no Docker/server needed.

## Generate the synthetic data

```bash
python generate.py --domain careflow
```

Produces, under `data/careflow/`:
- `corpus/{markdown,pdf}/` -- 14 documents (6 policy docs + 8 specialty
  handbooks). The cost-share schedule and pre-authorization matrix are
  rendered from the same `PLANS`/`SPECIALTIES` spec in `generate.py` that the
  co-pay calculator tool reads, so the numbers can't disagree.
- `mock_ehr/*.csv` -- patients, payers, plans, plan_specialty_coverage,
  eligibility, appointments, referrals.
- `intake_messages/intake_messages.jsonl` -- ~48 synthetic messages across
  phone/web/email/SMS, ~1/5 seeking clinical advice (must be refused), ~1/6
  missing insurance ID or specialty, several in Indian English.

Regenerate only one piece with `--only corpus|mock_ehr|intake`.

## Build the RAG index

```bash
python scripts/build_index.py
```

Chunks the markdown corpus, embeds it, and builds both the Qdrant dense
index and the BM25 sparse sidecar index used by the hybrid retriever.

## Run the demo

```bash
python demo/run_demo.py
```

Walks through: parsing an intake message, booking a Cardiology slot and
checking a copay via the insurance agent, storing/summarizing long-term
patient memory, answering a grounded policy question with citations, and a
clinical question being refused and flagged to `data/careflow/human_queue.jsonl`.

## Run the LangGraph workflow (M5)

```python
from app.graph.intake_workflow import run_intake_workflow, resume_intake_workflow

result = run_intake_workflow("What dose of amoxicillin should I give my child?", "sms", session_id="s1", patient_id="P00001")
# result["status"] == "needs_human_review" -- the graph is paused, waiting on a human.

final = resume_intake_workflow("s1", "confirm_escalate")  # or "override_proceed"
```

A non-flagged message runs straight through intake -> eligibility -> referral
routing -> finalize without pausing. State is checkpointed to
`data/careflow/memory/workflow_checkpoints.sqlite`, so `resume_intake_workflow`
works even if it's a separate process invocation (e.g. two different API
requests) from the one that started the run.

## Run the MCP server (M6)

```bash
python -m app.mcp_server.server
```

Exposes the mock EHR/scheduling tools (appointments, eligibility, copay,
referrals) over stdio. `app/agents/referral_agent.py` is the agent that
actually talks to it (via `app/tools/mcp_client.py`); `insurance_agent.py`
keeps its existing direct dispatch to the same underlying functions -- see
"Design notes" below for why.

## Run the golden eval (M8)

```bash
python scripts/run_golden_eval.py
```

Runs all 20 cases in `data/careflow/eval/golden_eval.jsonl` through the real
pipeline entrypoints and reports pass/fail per case, plus a full result
dump at `data/careflow/eval/golden_eval_results.jsonl`.

## Run the FastAPI service (M8)

```bash
uvicorn app.api.main:app --reload
```
Then see http://127.0.0.1:8000/ for `UI`
Then see `/docs` for the interactive Swagger UI, or:

```bash
curl -X POST localhost:8000/insurance/chat \
  -H "Content-Type: application/json" \
  -d '{"raw_text": "Book me a cardiology slot, insurance ID INS-12345678", "channel": "web_form"}'
```

## Tests

```bash
pytest
```

Guardrail and tool-logic tests run without any API key. Intake, agent, and
RAG tests that call the LLM skip automatically unless `OPENAI_API_KEY` is set
(and RAG retrieval tests skip until `scripts/build_index.py` has been run).

## Design notes

- **Single source of truth for money.** `data/careflow/mock_ehr/plans.csv`
  and `plan_specialty_coverage.csv` are the only place co-pay/deductible/
  pre-auth numbers are defined. `generate.py` renders the Cost-Share Schedule
  and Pre-Authorization Matrix documents from them, and
  `app/tools/copay_calculator.py` reads them directly -- so the corpus, the
  tool, and the groundedness check can never disagree.
- **Guardrails are defense-in-depth**, not just a system-prompt instruction:
  a regex/keyword layer (`app/guardrails.py`) backs up the LLM classifier,
  and both the intake agent and the insurance/RAG agents check *before*
  invoking any tool-use or answer-generation logic.
- **Groundedness gating**: the RAG agent never returns an ungrounded answer
  to the patient -- if the LLM-judge finds an unsupported claim, the agent
  falls back to "I don't have that on file" and flags a human coordinator.
- **Human-in-the-loop is a hard checkpoint, not a log line.** The M5 graph's
  `human_in_the_loop_node` calls LangGraph's `interrupt()` and truly pauses
  -- nothing downstream (escalation, eligibility, referral) runs until
  `resume_intake_workflow` is called with an explicit decision. The node
  does nothing else besides that one call, because LangGraph re-runs a node
  function from the top on every resume.
- **MCP split, scoped deliberately.** The mock EHR/scheduling functions are
  the same Python functions either way; `app/mcp_server/server.py` just
  re-exposes them over stdio. Only the new Referral Tracking agent
  (M6) is wired to call them through an MCP client -- `insurance_agent.py`
  (M2, already tested) keeps its direct dispatch. This satisfies "expose ...
  as an MCP server" without rewriting an already-working, already-tested
  agent's tool-call plumbing.
- **Resilience wraps technical failures, not business outcomes.** The
  retry/circuit-breaker layer in `app/resilience/` only ever sees real
  exceptions (a CSV read/write failure, a network error) -- a normal "no
  eligibility record found" response is not treated as a failure to retry.
- **Tracing degrades to a no-op, never to a hard dependency.** Both the
  LiteLLM Langfuse callback and the `@observe` decorator only activate when
  `LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY` are set; every test and demo
  path here runs identically with or without Langfuse configured.
